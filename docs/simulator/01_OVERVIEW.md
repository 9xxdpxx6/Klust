# 📋 Обзор: Банковский симулятор

## 🎯 Цель проекта

Разработать **стратегию и прототип** банковского симулятора "Финансовый Консультант" для обучения студентов работе с клиентами банка.

**Важно**: Это НЕ полноценная реализация, а архитектурное решение и proof-of-concept для дальнейшей разработки.

---

## 📊 Анализ требований заказчика

### ✅ Что можно реализовать в текущем стеке (Laravel + Vue 3)

1. **Интерфейс консультанта** ✅
   - Vue 3 компоненты для UI
   - TailwindCSS для стилизации
   - PrimeVue для сложных компонентов (DataTable, Dialog, Chart)

2. **Логика скоринга и расчетов** ✅
   - PHP сервисы для формул скоринга
   - Кредитный калькулятор (аннуитетный платеж)
   - Калькулятор вкладов (с капитализацией)
   - Хранение состояния в JSON поле `state` модели `SimulatorSession`

3. **Типы клиентов и сценарии** ✅
   - Генерация клиентов через фабрики/сидеры
   - Хранение шаблонов клиентов в БД или конфиге
   - Случайная или сценарная генерация

4. **Система оценки** ✅
   - Интеграция с существующей системой `score` в `SimulatorSession`
   - Начисление очков через `ProgressLogService`
   - Связь с навыками (Skills) через кейсы

5. **Геймификация** ✅
   - Уже есть система Badges (Достижения)
   - Уже есть система Skills (Навыки)
   - Можно добавить новые бейджи для симулятора

---

### ⚠️ Что нужно адаптировать/упростить

#### 1. NLP для диалога ⚠️

**❌ НЕ делать**: Полноценный NLP с spaCy/Rasa/GPT API
- Слишком сложно для MVP
- Требует внешние сервисы
- Задержки API (2-5 секунд)
- Платные API
- Непредсказуемость ответов

**✅ Вместо этого**:
- Система выбора реплик из предопределенного списка (branching dialogue)
- Простой pattern matching для ключевых слов
- Можно добавить GPT API позже как опциональную фичу

#### 2. Машинное обучение для скоринга ⚠️

**❌ НЕ делать**: Реальный ML с Scikit-learn
- Избыточно для симулятора
- Требует обучение моделей
- Сложность поддержки

**✅ Вместо этого**:
- Детерминированные формулы скоринга (как описано заказчиком)
- Настраиваемые веса и коэффициенты через админку
- Можно добавить "реалистичность" через случайные факторы

#### 3. Backend на Python ❌

**❌ НЕ делать**: Отдельный Python сервис
- Нарушает монолитную архитектуру
- Добавляет сложность развертывания
- Дублирование логики

**✅ Вместо этого**:
- Вся логика в Laravel сервисах
- PHP отлично справляется с математическими расчетами

#### 4. PostgreSQL ❌

**❌ НЕ менять**: Текущая БД MySQL/MariaDB работает отлично
- Нет необходимости в смене БД
- JSON поля поддерживаются

**✅ Вместо этого**: Использовать существующую БД

## 💡 Приоритеты реализации

### Приоритет 1: Простота и понятность
- Начать с простых решений
- Использовать branching dialogue (дерево выбора) вместо NLP
- Детерминированные формулы вместо ML

### Приоритет 2: Расширяемость
- Структура должна позволять добавлять новые типы клиентов
- Формулы должны быть настраиваемыми
- Диалог должен быть легко редактируемым

### Приоритет 3: Интеграция с существующей системой
- Использовать `SimulatorSession.state` для хранения состояния
- Интегрироваться с `ProgressLogService` для начисления очков
- Связывать с Skills через кейсы (если нужно)
