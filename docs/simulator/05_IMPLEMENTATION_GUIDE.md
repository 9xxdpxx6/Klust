# 🛠️ Руководство по реализации

## UI/UX рекомендации

### ⚠️ ВАЖНО: Игровая визуализация

**Цель**: Создать **игровую визуализацию** в стиле job simulator (3D/low-poly офис), а НЕ визуальную новеллу.

**Подробности**: См. [06_VISUALIZATION.md](06_VISUALIZATION.md)

### Компоненты Vue

1. **`Office3DScene.vue`** - Основная 3D сцена (Three.js или CSS 3D)
2. **`MonitorScreen.vue`** - Монитор на столе с интерфейсом
3. **`ClientCharacter.vue`** - 3D/2D модель клиента (сидящий напротив)
4. **`DeskItems.vue`** - Предметы на столе (телефон, документы, калькулятор)
5. **`BankInterface.vue`** - Интерфейс банковской системы (на мониторе)
6. **`ClientProfilePanel.vue`** - Панель данных клиента (UI поверх сцены)
7. **`CreditCalculator.vue`** - Калькулятор кредита (в UI)
8. **`ScoringResult.vue`** - Результат скоринга (визуализация на мониторе)
9. **`ActionButtons.vue`** - Кнопки действий

### Стилизация

- **Визуальный стиль**: Low-poly / Stylized (как в job simulator)
- **3D сцена**: Офисное кресло консультанта (first-person view)
- **Цвета**: Синий (#1E40AF), коричневый (#8B4513), бежевый (#F5DEB3)
- **Шрифты**: Профессиональные, читаемые
- **Иконки**: Простые, flat design
- **Графики**: Chart.js для визуализации платежей (на мониторе)

## Интеграция с существующей системой

### Навыки (Skills)

Создать навыки для банковского симулятора:
- "Финансовое консультирование"
- "Кредитный скоринг"
- "Работа с клиентами"
- "Банковские продукты"

### Достижения (Badges)

Добавить бейджи:
- "Первый кредит" - одобрил первый кредит
- "Эксперт по вкладам" - открыл 10 вкладов
- "Мастер скоринга" - правильный скоринг 10 раз подряд
- "Скоростной консультант" - завершил симулятор за < 15 минут

## Что НЕ делать

### 1. ❌ Отдельный Python сервис
**Почему**: Нарушает монолитную архитектуру, добавляет сложность

### 2. ❌ Полноценный NLP с GPT
**Почему**: Для MVP избыточно, можно добавить позже

### 3. ❌ Реальный ML для скоринга
**Почему**: Детерминированные формулы достаточно для симулятора

### 4. ❌ Смена БД на PostgreSQL
**Почему**: MySQL работает отлично, нет необходимости

### 5. ❌ Сложная система чата в реальном времени
**Почему**: Для симулятора достаточно пошагового диалога

## Что делать правильно

### 1. Использовать существующую инфраструктуру
- `SimulatorSession.state` для хранения состояния
- `ProgressLogService` для начисления очков
- Существующие контроллеры и роуты

### 2. Делать расширяемым
- Конфиги для настройки формул
- Шаблоны клиентов легко редактировать
- Диалог структурирован (JSON/YAML)

### 3. Интегрироваться с системой навыков
- Связывать симулятор с кейсами (если нужно)
- Начислять очки навыкам при завершении
- Добавить новые бейджи для симулятора

## Приоритеты реализации

### Приоритет 1: Простота и понятность
- Начать с простых решений
- Использовать branching dialogue (дерево выбора) вместо NLP
- Детерминированные формулы вместо ML

### Приоритет 2: Расширяемость
- Структура должна позволять добавлять новые типы клиентов
- Формулы должны быть настраиваемыми
- Диалог должен быть легко редактируемым

### Приоритет 3: Интеграция с существующей системой
- Использовать `SimulatorSession.state` для хранения состояния
- Интегрироваться с `ProgressLogService` для начисления очков
- Связывать с Skills через кейсы (если нужно)
