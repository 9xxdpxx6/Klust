## 1. Подготовка тестовых данных

### TC-1.1: Проверка наличия навыков в системе
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Админ |
| **Шаги** | 1. Перейти в `/admin/skills` <br> 2. Убедиться, что есть минимум 3 навыка (например: «Python», «Анализ данных», «Командная работа») |
| **Ожидаемый результат** | Список навыков отображается, навыки имеют названия и категории |
| **Если нет навыков** | Создать навыки через кнопку «Добавить навык» |

### TC-1.2: Проверка наличия бейджей
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Админ |
| **Шаги** | 1. Перейти в `/admin/badges` <br> 2. Убедиться, что есть бейджи с разными порогами `required_points` (например: 50, 100, 500 очков) |
| **Ожидаемый результат** | Список бейджей с порогами отображается |
| **Если нет бейджей** | Создать 3 бейджа: «Новичок» (50 очков), «Ученик» (100 очков), «Мастер» (500 очков) |

### TC-1.3: Проверка наличия симулятора
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Админ |
| **Шаги** | 1. Перейти в `/admin/simulators` <br> 2. Убедиться, что есть хотя бы 1 симулятор (например: Банковский симулятор) |
| **Ожидаемый результат** | Симулятор отображается в списке |

### TC-1.4: Зафиксировать начальные баллы студентов
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Админ |
| **Шаги** | 1. Перейти в `/admin/users` <br> 2. Открыть профили студентов 1, 2, 3 <br> 3. Записать текущие значения `total_points` для каждого |
| **Ожидаемый результат** | Записаны начальные значения баллов |

> 📝 **Записать**: Студент1 = ___ очков, Студент2 = ___ очков, Студент3 = ___ очков

## 2. Создание кейсов

### TC-2.1: Создание кейса через админку (статус «Активный»)
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Админ |
| **Шаги** | 1. Перейти в `/admin/cases/create` <br> 2. Заполнить: <br> — Название: «Тестовый кейс E2E #1» <br> — Описание: «Описание тестового кейса для проверки начисления баллов» <br> — Партнёр: выбрать тестового партнёра <br> — Дедлайн: дата через 7 дней от текущей <br> — Размер команды: 3 <br> — Сложность: «Средний» (или любая доступная) <br> — Статус: **Активный** <br> — Симулятор: привязать банковский симулятор <br> — Навыки: выбрать 2-3 навыка <br> 3. Нажать «Создать кейс» |
| **Ожидаемый результат** | Кейс создан, перенаправление на страницу кейса, flash-сообщение «Кейс успешно создан» |
| **Проверить** | — Статус = «active» <br> — Привязанные навыки отображаются <br> — Симулятор привязан <br> — Партнёр указан |

### TC-2.2: Создание кейса через партнёрский портал
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Партнёр |
| **Шаги** | 1. Перейти в `/partner/cases/create` <br> 2. Заполнить: <br> — Название: «Тестовый кейс E2E #2» <br> — Описание: произвольное <br> — Дедлайн: дата через 14 дней <br> — Размер команды: 2 <br> — Сложность: «Лёгкий» <br> — Навыки: выбрать 1-2 навыка <br> 3. Нажать «Создать» |
| **Ожидаемый результат** | Кейс создан, перенаправление на страницу кейса |

### TC-2.3: Создание кейса с дедлайном «завтра» (для теста автозакрытия)
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Админ |
| **Шаги** | 1. Создать кейс «Тестовый кейс E2E #3» <br> 2. Дедлайн: завтрашняя дата <br> 3. Статус: **Активный** <br> 4. Размер команды: 1 <br> 5. Привязать навыки и симулятор |
| **Ожидаемый результат** | Кейс создан со статусом «active» |

### TC-2.4: Создание кейса в статусе «Черновик»
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Админ |
| **Шаги** | 1. Создать кейс «Черновик E2E» <br> 2. Статус: **Черновик** <br> 3. Остальные поля заполнить |
| **Ожидаемый результат** | Кейс создан, статус = «draft» |

## 3. Подача заявок студентами

### TC-3.1: Подача заявки студентом (соло-лидер)
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Студент 1, email подтверждён |
| **Шаги** | 1. Перейти в `/student/cases` (каталог кейсов) <br> 2. Найти «Тестовый кейс E2E #1» <br> 3. Открыть карточку кейса <br> 4. Нажать «Подать заявку» <br> 5. Заполнить мотивацию: «Хочу развить навыки анализа данных» <br> 6. Отправить заявку |
| **Ожидаемый результат** | — Заявка создана со статусом «pending» (ожидает) <br> — Flash-сообщение «Заявка успешно подана» <br> — На странице кейса кнопка заявки заменена на статус «Ожидает рассмотрения» |

### TC-3.2: Подача заявки с командой
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Студент 2 |
| **Шаги** | 1. Перейти на «Тестовый кейс E2E #1» (команда = 3) <br> 2. Нажать «Подать заявку» <br> 3. Указать мотивацию <br> 4. Добавить участника команды: email Студента 3 <br> 5. Отправить |
| **Ожидаемый результат** | — Заявка создана со статусом «pending» <br> — Команда: Студент 2 (лидер) + Студент 3 (участник) <br> — Общий размер команды = 2 |

### TC-3.3: Подача заявки на кейс с размером команды = 1
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Студент 1 |
| **Шаги** | 1. Перейти на «Тестовый кейс E2E #3» (команда = 1) <br> 2. Подать заявку без участников команды |
| **Ожидаемый результат** | Заявка создана, команда = 1 (только лидер) |

### TC-3.4: Проверка дублирования заявки
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Студент 1 (уже подал заявку на кейс #1) |
| **Шаги** | 1. Попытаться снова подать заявку на «Тестовый кейс E2E #1» |
| **Ожидаемый результат** | Ошибка «Вы уже подали заявку на этот кейс» |

### TC-3.5: Заявка на кейс-черновик (негативный)
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Студент 1 |
| **Шаги** | 1. Попробовать перейти на кейс «Черновик E2E» в каталоге |
| **Ожидаемый результат** | Кейс в статусе «draft» **НЕ** отображается в каталоге для студента |

### TC-3.6: Проверка «Мои кейсы»
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Студент 1 (имеет заявки) |
| **Шаги** | 1. Перейти в `/student/cases/my` <br> 2. Проверить вкладки: Текущие / Ожидающие / Отклонённые |
| **Ожидаемый результат** | — Вкладка «Ожидающие»: видны поданные заявки со статусом «pending» <br> — Информация о кейсе, партнёре и команде корректна |

## 5. Прохождение симулятора и начисление баллов

### TC-5.1: Запуск симулятора студентом
| Поле | Значение |
|------|----------|
| **Предусловие** | Авторизоваться как Студент 1 |
| **Шаги** | 1. Перейти в `/student/simulators` <br> 2. Найти симулятор, привязанный к кейсу #1 <br> 3. Нажать «Начать» |
| **Ожидаемый результат** | — Создана `SimulatorSession` с `started_at` <br> — Перенаправление на страницу сессии `/student/simulators/session/{id}` |

### TC-5.2: Прохождение симулятора (высокий балл ≥ 90)
| Поле | Значение |
|------|----------|
| **Предусловие** | Студент 1 начал сессию симулятора |
| **Шаги** | 1. Пройти симулятор, стараясь получить высокий балл (≥ 90) <br> 2. Завершить сессию |
| **Ожидаемый результат** | — Сессия завершена: `completed_at` установлено, `score` ≥ 90 <br> — **Начислены баллы** по формуле: `score + 20` (бонус за ≥90) <br> — Баллы добавлены к `student_profile.total_points` <br> — Создана запись в `progress_logs` с `action = 'simulator_completion'` <br> — Навыки кейса обновлены в `user_skills` (points_earned увеличены) |

### TC-5.3: Прохождение симулятора (средний балл 50-74)
| Поле | Значение |
|------|----------|
| **Предусловие** | Студент 2 авторизован, подать одобренную заявку (или сразу запустить симулятор) |
| **Шаги** | 1. Пройти симулятор, набрав 50–74 балла <br> 2. Завершить |
| **Ожидаемый результат** | — Начислены баллы = `score` (без бонуса) <br> — `total_points` обновлено <br> — ProgressLog создан |

### TC-5.4: Прохождение симулятора (низкий балл < 50)
| Поле | Значение |
|------|----------|
| **Предусловие** | Студент 3 |
| **Шаги** | 1. Пройти симулятор, набрав < 50 баллов <br> 2. Завершить |
| **Ожидаемый результат** | — Начислены баллы = `max(10, score × 0.5)` (минимум 10) <br> — `total_points` обновлено |

### TC-5.5: Проверка начисления баллов в навыках кейса
| Поле | Значение |
|------|----------|
| **Предусловие** | Студент прошёл симулятор привязанный к кейсу с навыками |
| **Шаги** | 1. Перейти в `/student/skills` <br> 2. Найти навыки, привязанные к кейсу <br> 3. Проверить `points_earned` |
| **Ожидаемый результат** | — Навыки кейса имеют увеличенные `points_earned` <br> — Уровень навыка (`level`) пересчитан: <br> &nbsp;&nbsp; 0-99 → level 1 <br> &nbsp;&nbsp; 100-249 → level 2 <br> &nbsp;&nbsp; 250-499 → level 3 <br> &nbsp;&nbsp; и т.д. |

### TC-5.6: Повторное прохождение симулятора
| Поле | Значение |
|------|----------|
| **Предусловие** | Студент 1 уже прошёл симулятор 1 раз |
| **Шаги** | 1. Запустить тот же симулятор ещё раз <br> 2. Пройти и завершить |
| **Ожидаемый результат** | — Создана новая сессия <br> — Баллы начислены повторно (кумулятивно) <br> — `total_points` увеличились ещё раз |

## 7. Проверка начисления баллов и уровней

### TC-7.1: Проверка total_points после прохождения симулятора
| Поле | Значение |
|------|----------|

## 🔧 Полезные SQL-запросы для верификации

```sql
-- Проверить total_points студента
SELECT u.id, u.name, sp.total_points 
FROM users u 
JOIN student_profiles sp ON u.id = sp.user_id 
WHERE u.id IN (студент1_id, студент2_id, студент3_id);

-- Проверить записи progress_logs
SELECT pl.*, s.name as skill_name 
FROM progress_logs pl 
JOIN skills s ON pl.loggable_id = s.id AND pl.loggable_type = 'App\\Models\\Skill'
WHERE pl.user_id = {student_id} 
ORDER BY pl.created_at DESC;

-- Проверить user_skills (баллы по навыкам)
SELECT us.*, s.name as skill_name 
FROM user_skills us 
JOIN skills s ON us.skill_id = s.id 
WHERE us.user_id = {student_id};

-- Проверить бейджи студента
SELECT b.name, b.required_points, ub.earned_at, ub.level 
FROM user_badges ub 
JOIN badges b ON ub.badge_id = b.id 
WHERE ub.user_id = {student_id};

-- Проверить историю статусов заявки
SELECT cash.*, 
  old_s.name as old_status, 
  new_s.name as new_status,
  changer.name as changed_by_name
FROM case_application_status_histories cash
LEFT JOIN application_statuses old_s ON cash.old_status_id = old_s.id
LEFT JOIN application_statuses new_s ON cash.new_status_id = new_s.id
LEFT JOIN users changer ON cash.changed_by = changer.id
WHERE cash.case_application_id = {application_id}
ORDER BY cash.changed_at DESC;

-- Проверить сессии симулятора
SELECT ss.*, sim.name as simulator_name 
FROM simulator_sessions ss 
JOIN simulators sim ON ss.simulator_id = sim.id 
WHERE ss.user_id = {student_id} 
ORDER BY ss.created_at DESC;

-- Проверить статус кейса
SELECT id, title, status, deadline FROM cases WHERE id = {case_id};
```

## 📌 Формула начисления баллов (справочник)

| Score симулятора | Начисляемые баллы | Описание |
|------------------|-------------------|----------|
| null             | 10                | Значение по умолчанию |
| < 50             | max(10, score × 0.5) | Минимум 10 очков |
| 50–74            | score             | Стандартные очки |
| 75–89            | score + 10        | Бонус за хорошую работу |
| ≥ 90             | score + 20        | Бонус за отличную работу |
